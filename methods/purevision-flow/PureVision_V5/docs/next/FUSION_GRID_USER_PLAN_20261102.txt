四、六组结构

C_joint：
每个位置拼接光流64维与RGB256维：
Linear(320,64) → LayerNorm → 加固定位置编码。

C_sep：
光流：Linear(64,64) → LayerNorm；
RGB：Linear(256,64) → LayerNorm。
两路分别加入相同位置向量和对应模态嵌入。

模态嵌入为两条64维向量，在隔离的可复现随机数上下文中以Normal(0,0.02)初始化。

sep顺序：
全部光流token，然后全部RGB token；
各路内部均为时间→行→列。

F23仅保留S23的光流输入处理及对应模态嵌入；
R23仅保留S23的RGB输入处理及对应模态嵌入。
独立训练，不用输入清零代替，不保留未参与预测的另一支可训练模块。

所有组共同保持：
- 两层分别初始化的TransformerEncoderLayer；
- d_model=64，4个注意力头；
- FFN 64→128→64，GELU；
- post-norm，dropout=0；
- bias、LayerNorm eps等沿用历史C；
- 无额外最终LayerNorm、CLS、查询token、注意力池化或因果mask。

输出token均值汇总成64维，拼接按历史DT_SCALE_SECONDS处理的4个dt：
Linear(68,192) → GELU → Linear(192,2)。

本轮保留上述LayerNorm，不加L2单位长度归一化、幅值旁路或其他归一化。

五、初始化与位置编码

先复现历史C，再匹配六组初始化。

必须保留原build_triplet()初始化来源：
按原顺序构建A/B/C，再将B的输入投影、LayerNorm和速度头复制给C。
该流程得到的未训练C作为J23参照，不能只在新工厂设置seed42就声称复现。

新J23应与原C：

- 少量固定缓存输入，在同设备、FP32、eval下前向一致；
- 记录容差，建议atol=1e-6、rtol=1e-5。

显式复制：
- J23/J46全部可训练初始参数一致；
- S23/S46全部可训练初始参数一致，包括模态嵌入；
- 六组共同Transformer和速度头初始参数一致；
- F23/R23输入处理与S23对应分支匹配。

复制后各组参数存储独立。
新增投影采用记录明确的PyTorch Linear默认初始化，在隔离seed42上下文构建。

跨网格只复制可训练参数；位置编码buffer分别生成，不整份加载不同网格的state_dict。

位置编码沿用历史正弦余弦规则：

每轮完整验证；
按dev整体EPE选best，严格相同时选更早轮次。

反向传播损失保持：
F.smooth_l1_loss(
    prediction / scale,
    target / scale,
    beta=1,
    reduction="mean"
)
scale=[5,1]，输入为完整[B,2]张量。

从同一次前向的detached预测记录loss_x、loss_y，不增加训练前向、不参与反向、不改变总损失：
loss_x对应vx/5，loss_y对应vy；
两轴均按窗口数汇总；
(loss_x+loss_y)/2应在数值容差内匹配总损失。

保留train_online_loss_x/y与dev_loss_x/y。
在线训练损失不是所选checkpoint的train EPE。

dev EPE按全部验证窗口等权计算；不能等权平均不同大小batch或场景的均值。场景等权指标可另列。

不单独早停、调整学习率、层数、预算或loss scale；不新增数据增强、样本重加权或侧向过采样。

八、提速与GPU调度——本轮重点

只采用不改变实验协议的轻量优化，不开展性能研究项目。

1. 优先复用

复用已有2×3缓存、训练循环、评估、配置和发布工具。

不做无关重构，不重新打包数据、重新训练编码器或重算RAFT。

2. 缓存常驻显存

缓存训练中，优先一次性将所需特征和标签载入对应GPU，随后按固定顺序在GPU上取batch，减少每步CPU索引和CPU→GPU搬运。

若设备条件不适合驻留，使用CPU内存缓存及合理传输，不改变精度或训练batch。

在已有固定输入预检内确认批次内容与前向保持一致，不额外开性能对照实验。

3. 减少同步与I/O

避免每batch写状态JSON、查询外部GPU命令或落盘checkpoint。
常规batch日志限频，例如每50步；状态至少每30秒或每个epoch更新一次。
首次启动、异常、验证完成和训练结束立即记录。

损失分量轻量累计，尽量在日志/epoch边界统一转CPU；保留必要数值检查。
每轮保存完整恢复点即可，取消正式训练中的每100批完整checkpoint覆盖。

不引入torch.compile、CUDA Graphs、新优化器或改变数学实现的加速方案，以免编译、调试或数值变化拖慢本轮。

每轮dev验证保持完整。
