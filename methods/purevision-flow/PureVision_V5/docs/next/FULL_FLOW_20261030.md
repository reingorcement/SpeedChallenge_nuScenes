## 文件、数值合同与复用

数据根：`/mnt/sdb2/Workspace/zhangyu/dataset/nuscenes`。

缓存根：`derived/optical_flow/raft_large_C_T_SKHT_V2_1024x576_fwd_v1_20261030/`，其下：

- `index/index.json` 及 group 文件：无标签索引，包含源元数据 SHA 和原分区映射身份。
- `v1.0-trainval/CAM_FRONT/v5_flow_v2/<token前两位>/<source>_<target>.native.pt` 与 `.pt`。
- `v1.0-test/CAM_FRONT/v5_flow_v2/...`：同合同，独立版本目录。
- `packed_train_core_dev/`：仅原监督 manifest 的 train_core/dev，按依赖自动打包。

RAFT 为 torchvision RaftLarge `C_T_SKHT_V2`，冻结、FP32、TF32关闭、12次迭代，输入宽×高1024×576，RGB双线性缩放且antialias=false，归一化到[-1,1]。原生向量 float32，单位是输入尺寸上的像素位移，保留符号和幅值；派生向量 float16、宽×高128×72，u/v均乘1/8；valid按既有有限值和终点合法规则，再最近邻缩放。前向版本不计算FB，FB占位全零且明确fb_available=false。本阶段不改变 `purevision_v5/flow.py`。

旧 pilot 的9270对1024流可复用：源生成commit `be327b7f91f5f7e5ba46b70dede116a21c551652`；数值源码SHA `132a1074a13c3dc2abedf165d663713de7a67269aebc382853485bed23c9bdb3`。复用清单钉住原packed_index SHA、每对compact SHA、native SHA与身份、图像SHA/时间、权重、环境及数值合同。跨磁盘复制原字节，不改写旧包的generation_code。原CPU打包code的remote字段为null，不冒充生成时远端校验；native生成来源必须有原始已推送证明。

原旧入口对不同generation commit严格拒绝，不能直接把复制后的旧包认作本次生成。本次新增显式来源白名单和验证包装，保持数值实现不变。已经完整写入的对会核验并跳过，native已提交而compact缺失可恢复；损坏/来源变化会明确失败，不自动忽略。每对原子保存，报告记录created/reused/recovered/adopted、累计字节、首尾样例及顺序pair digest。

索引SHA：`b42d3c541d65ecd372bae62026a1fd1e537f533d56b66632ca8eef1be66f0816`；identity：`1f33c9939baaec4d41ad0b084923787f50acc71f73e988eb3e6d0bdb1e7f8246`。索引先于正式代码commit生成，元数据如实记录开发工作树dirty=true及generator源码SHA；正式RAFT另记录已推送固定commit，二者不能混淆。

## 开发与验证

新增 `full_flow_index.py`/`index_full_flow.py` 负责无标签数据索引；`full_flow_cache.py`/`prepare_full_flow.py` 负责来源验证、复用、原子输出和报告；`full_flow_pipeline.py` 只管理三个生成分片、原train/dev打包、独立收尾检查。`collect_full_flow.py` 重算每片pair覆盖digest，抽查首尾包并检查packed数组SHA及原窗口pair全集。最终核验不声称重新哈希约1.38TB全部native；生成时每对已验证，最终独立抽查范围在报告中明确列出。

源码自审重点：无pose/标签进入生成入口；原数据/划分不改；每个场景只属于一个分片；GPU互斥；新旧缓存来源不混写；运行目录冻结；正式commit必须推送并核实；现有训练、FB和分辨率预试验接口保持回归覆盖。新生成时由原save_pair检查输入、构造数值包并绑定native字节SHA，不声称每对新包又做了完整磁盘重载。真实HDD烟测使用独立目录，其开发态生成物不混入正式缓存。

真实烟测结果见 [综合凭证](evidence/full_generation_smoke_summary_20261030.json)：三卡两次短批新增段合计约5.745/5.141对每秒，两卡约4.756对每秒；每卡batch8峰值CUDA分配9,452,956,672字节。三卡96对全部完成，再跑96对全部reused、零新写、零CUDA分配；单对跨NVMe/HDD复制及native-only恢复的字节SHA均一致。实际HDD活动窗口约32.53MB/s写入、await14.90ms、util75.3%，同步存储限制明显。故保留三卡但不承诺线性加速；222969对新算部分初估10.8–13.0小时，需用正式前1000对更新，另计复用、打包和收尾时间。旧pilot基于NVMe的两卡估时不适用于本次直接HDD生成。

最终整套回归：**268 passed / 11.71s**。测试覆盖原训练/评价/FB接口及新增索引、缓存来源、恢复、调度和收尾边界。

## 运行管理

控制根 `ART=/home/zhangyu/.local/share/speedest-v5-next` 保持用户私有，网络配置和巡视记录不放共享数据目录。数据盘为本机HDD、fuseblk文件系统，启动前实际核对可用空间和原子复制。原始图像与旧缓存均保留。

三个互斥分片：GPU0 77623对，GPU1 77277对，GPU2 77339对；每卡一个batch8任务、4 CPU线程。实际三GPU短批验证通过后才按此安排启动，不能把三张卡机械解释为三倍吞吐。`pack_train_dev` 等待三片完成；`verify_full_cache` 再等待打包完成。未授权后续模型训练由本队列自动启动。

发布分支 `method/purevision-v5-next`，报告分支 `results/purevision-v5-next`。正式代码与配置先提交、推送、核对准确commit，添加 `v5-code-<commit前12位>`，从该commit建立 `ART/code/<commit前12位>/` detached worktree。真实commit、完整argv、身份和当前状态在 `ART/pipeline/<prefix>/plan.json` / `status.json`；日志 `ART/logs/<prefix>_<job>.log`。首个prefix计划为 `20261030_full_nuscenes_front1024`，是否已启动必须看实际状态，本文不是启动凭证。

固定版本的正式启动命令为（CODE指向上述固定worktree的V5目录）：

```bash
"$PY" -B "$CODE/full_flow_pipeline.py" --root "$ART" --index "$FULL/index/index.json" --data-manifest /mnt/sdb2/Workspace/zhangyu/01_speedest_vision_artifacts/v5/data/nuscenes_proxy_v1/dataset.json --output-root "$FULL" --adoption "$ART/plans/full_nuscenes_adoption_20261030.json" --run-prefix 20261030_full_nuscenes_front1024
```

协调器及每个worker均挂独立tmux。查看：`tmux ls`；连接：`tmux attach -t v5next_20261030_full_nuscenes_front1024_flow1024_0`；日志用 `tail -n 30 <日志路径>`；完整状态用固定源码 `monitor.py --root "$ART" --json`。只停止明确的本轮worker：连接后Ctrl-C，并检查对应报告及已提交文件。不可全局kill其他作业。

协调器意外退出但worker仍在运行时，从同一固定源码以 `full_flow_pipeline.py --resume-plan "$ART/pipeline/<prefix>/plan.json"` 重连已有队列，不重建含瞬时磁盘空间的计划、不重复启动活跃任务、不重启终态worker。生成worker失败后先定位；修复提交/推送后用新prefix和明确兼容来源恢复，原失败记录保留。正常损失波动与本阶段无关，因为当前没有测速模型训练。

每5分钟服务器检查，每30分钟Astra只读巡视；检查进程、每片实际pairs/速度、日志异常、GPU/显存、数据盘空间、最近完成包与报告更新时间。它不自动更改算法或重启任务。安装记录和实际触发成功记录分开：必须完成一次真实cron probe和报告读取证据后才声称已验证；后续故障保留失败记录。所有本轮job终态后停止对应巡视，结果发布器仅在成功推送终态报告后停止。tmux依赖本机持续运行，机器断电/重启时仍依靠逐对原子缓存恢复。

覆盖证据：`ART/evidence/full_flow_coverage_20261030.json`；正式收尾：`ART/reports/full_flow_<prefix>/summary.json`及`.md`。代码可运行、生成运行中、生成完成和最终核验通过是不同状态。新的R02/Flex/融合实验安排依赖本阶段结果及用户研究决策，本阶段不预先宣称效果。
