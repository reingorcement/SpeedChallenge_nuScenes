# 运动学与动力学特征提取器数据接口说明

## 1. 文档目的

本文定义在 `FlexiNet_ChassisFusion` 中单独训练以下两个模块时，Dataset 与模型之间需要提供的数据接口：

1. **运动学特征提取器**：`ChassisSequenceEncoder`，从 CAN/底盘时间序列中学习运动状态特征。
2. **动力学特征提取器**：`CausalPhysicsVelocityEstimator` 及其可选的物理特征 GRU，从轮速、IMU、转向和可选轮胎力信号中递推纵向、侧向速度。

本文只讨论底盘运动学/动力学训练。视觉图像不是这两个提取器单独训练时的必要输入；当前统一 Dataset 仍会返回 `images`，但关闭视觉分支后模型不会使用它。

## 2. 坐标系、单位与时序约定

### 2.1 车辆坐标系

速度、加速度和横摆运动统一采用车辆质心处的车体坐标系：

| 量 | 正方向 | 单位 |
|---|---|---|
| `vx` | 车辆前进方向 | `m/s` |
| `vy` | 车辆左侧方向 | `m/s` |
| `ax` | 车辆前向加速度 | `m/s^2` |
| `ay` | 车辆左向加速度 | `m/s^2` |
| `yaw_rate` | 绕车体 Z 轴逆时针旋转 | `rad/s` |
| `steering_angle` | 左转为正，指道路轮等效转角 | `rad` |

`velocity=[vx,vy]` 标签由相邻 ego pose 的中心差分得到全局速度，再旋转到中心帧车体坐标系。ego pose 只用于监督标签，不进入 `fair_chassis` 输入。

### 2.2 因果时间窗口

主实验使用：

```yaml
chassis_window_sec: 1.0
chassis_hz: 20.0
online_mode: true
```

因此每个样本包含 `K=21` 个底盘时间点，覆盖 `[t_center-1.0 s, t_center]`。图像序列也以 `t_center` 为最后一帧，不再使用未来图像。模型只能读取当前时刻及历史信号，不能读取 `t_center` 之后的数据。

Batch 后主要张量形状约定：

```text
B：batch size
K：底盘时间步数
Ck：运动学输入维度，fair_chassis 下为 16
Cp：动力学规范输入维度，固定为 25
Fp：物理中间特征维度，固定为 18
```

## 3. 单独训练所需 Dataset 输出总览

| Dataset 字段 | 运动学训练 | 动力学训练 | 形状 | 物理含义 |
|---|---:|---:|---|---|
| `chassis` | 必需 | 非必需 | `[K,16]` | 原始 CAN/底盘运动学序列 |
| `physics_inputs` | 非必需 | 必需 | `[K,25]` | 统一 SI 物理信号序列 |
| `physics_valid_mask` | 非必需 | 必需 | `[K,25]` | 每个物理测量是否真实存在 |
| `physics_dt` | 非必需 | 必需 | `[K]` | 每次状态递推的时间间隔，单位 `s` |
| `chassis_current_index` | 推荐 | 推荐 | 标量 | 当前时刻在底盘窗口中的索引；在线模式为 `K-1` |
| `base_velocity` | 残差训练必需 | 仅基准对比 | `[2]` | 基准速度，默认 `[base_vx,0]` |
| `velocity` | 必需 | 必需 | `[2]` | 监督真值 `[target_vx,target_vy]`，单位 `m/s` |
| `center_timestamp` | 推荐 | 推荐 | 标量 | 当前监督帧时间戳，单位 `us` |
| `scene_name` | 推荐 | 推荐 | 字符串 | 场景标识，用于分场景评估和状态隔离 |
| `center_token` | 推荐 | 推荐 | 字符串 | nuScenes 中心相机帧标识 |

禁止把不同 scene 的状态连续递推。Dataset 的每个样本都应被视为一个独立窗口，物理估计器在窗口开始处重新初始化状态。

## 4. 运动学特征提取器接口

### 4.1 输入端口

运动学编码器输入端口为：

```python
chassis: Tensor  # 单样本 [K,16]，Batch 后 [B,K,16]
```

`fair_chassis` 的 16 个通道顺序固定如下：

| 索引 | 字段名 | 当前数据来源与换算 | 实际物理含义 | 期望单位 |
|---:|---|---|---|---|
| 0 | `vehicle_speed` | `vehicle_monitor.vehicle_speed / 3.6` | 车辆控制器发布的整车纵向速度 | `m/s` |
| 1 | `odom_speed` | `zoe_veh_info.odom_speed / 3.6` | 车辆里程计综合速度 | `m/s` |
| 2 | `yaw_rate` | `radians(vehicle_monitor.yaw_rate)` | 车体绕 Z 轴横摆角速度 | `rad/s` |
| 3 | `throttle` | `vehicle_monitor.throttle / 1000` | 驾驶员/控制器加速踏板请求强度 | 无量纲，通常 `[0,1]` |
| 4 | `brake` | `vehicle_monitor.brake / 126` | 制动踏板或制动请求强度 | 无量纲，通常 `[0,1]` |
| 5 | `steering` | `vehicle_monitor.steering / 780` | 转向指令或方向盘转向量 | 当前为归一化量，尚不能直接视为 `rad` |
| 6 | `steering_feedback` | `steeranglefeedback.value / 7.7` | 实际转向反馈 | 当前为缩放量，尚不能直接视为道路轮转角 `rad` |
| 7 | `longitudinal_accel` | `zoe_veh_info.longitudinal_accel` | 车体前向加速度测量 | 代码按 `m/s^2` 使用，需审计 |
| 8 | `transversal_accel` | `zoe_veh_info.transversal_accel` | 车体横向加速度测量 | 代码按 `m/s^2` 使用，需审计符号 |
| 9 | `fl_wheel_speed` | `FL_wheel_speed / 1000` | 左前轮对应的轮周线速度 | 代码按 `m/s` 使用，需审计 |
| 10 | `fr_wheel_speed` | `FR_wheel_speed / 1000` | 右前轮对应的轮周线速度 | 代码按 `m/s` 使用，需审计 |
| 11 | `rl_wheel_speed` | `RL_wheel_speed / 1000` | 左后轮对应的轮周线速度 | 代码按 `m/s` 使用，需审计 |
| 12 | `rr_wheel_speed` | `RR_wheel_speed / 1000` | 右后轮对应的轮周线速度 | 代码按 `m/s` 使用，需审计 |
| 13 | `wheel_speed_mean` | 四轮线速度算术平均 | 四轮共同运动速度的简单统计量 | `m/s` |
| 14 | `wheel_speed_std` | 四轮线速度总体标准差 | 四轮不一致程度，可作为打滑/转弯代理 | `m/s` |
| 15 | `base_vx` | 优先 `vehicle_speed`，其次 `odom_speed`，最后四轮均值 | 当前可获得的纵向速度基准 | `m/s` |

### 4.2 输出端口

`ChassisSequenceEncoder` 的直接输出为：

```python
kinematic_feature: Tensor  # [B,Dk]
```

默认 `Dk=8`，由配置 `model.chassis_feature_dim` 决定。该向量是神经网络潜在特征，没有逐通道固定物理含义，不能把某一维直接解释为速度、加速度或侧偏角。

单独训练运动学分支时，需要在特征后接二维回归头：

```text
chassis [B,K,16]
  -> ChassisSequenceEncoder
  -> kinematic_feature [B,Dk]
  -> velocity residual head
  -> delta_velocity [B,2]
  -> pred_velocity = base_velocity + delta_velocity
```

对外训练输出端口为：

| 输出 | 形状 | 物理含义 | 单位 |
|---|---|---|---|
| `kinematic_feature` | `[B,Dk]` | 底盘时序潜在表示 | 无固定单位 |
| `delta_velocity` | `[B,2]` | 相对 `base_velocity` 的 `[delta_vx,delta_vy]` 修正 | `m/s` |
| `pred_velocity` | `[B,2]` | 运动学分支预测的质心 `[vx,vy]` | `m/s` |

对应现有单独训练配置为 `configs/velocity_xy_chassis_only.yaml`。

## 5. 动力学特征提取器输入接口

### 5.1 三个必需输入端口

```python
physics_inputs: Tensor      # [B,K,25]
physics_valid_mask: Tensor  # [B,K,25], bool
physics_dt: Tensor          # [B,K], s
```

`physics_valid_mask[b,k,c]=True` 表示该值来自真实有效测量。`False` 表示缺失；此时 `physics_inputs` 中对应的零只是占位，不能解释为“物理量等于零”。

### 5.2 `physics_inputs` 的 25 个端口

| 索引 | 字段名 | 实际物理含义 | 单位 | `fair_chassis` 可用性 |
|---:|---|---|---|---|
| 0 | `base_vx` | 当前纵向速度基准，用于窗口初始状态 | `m/s` | 可用 |
| 1 | `yaw_rate` | 车辆质心横摆角速度 | `rad/s` | 可用 |
| 2 | `steering_command` | 转向系统命令，理想情况下应换算为道路轮转角 | `rad` | 有原始缩放值，单位待审计 |
| 3 | `steering_feedback` | 实际道路轮等效转角，优先于命令值 | `rad` | 有原始缩放值，单位待审计 |
| 4 | `longitudinal_accel` | 车辆质心纵向加速度 `ax` | `m/s^2` | 可用，单位/符号待审计 |
| 5 | `lateral_accel` | 车辆质心侧向加速度 `ay` | `m/s^2` | 可用，单位/符号待审计 |
| 6 | `wheel_speed_fl` | 左前轮轮周线速度 | `m/s` | 可用，比例待审计 |
| 7 | `wheel_speed_fr` | 右前轮轮周线速度 | `m/s` | 可用，比例待审计 |
| 8 | `wheel_speed_rl` | 左后轮轮周线速度 | `m/s` | 可用，比例待审计 |
| 9 | `wheel_speed_rr` | 右后轮轮周线速度 | `m/s` | 可用，比例待审计 |
| 10 | `wheel_torque_fl` | 左前轮轮端驱动/制动力矩，正负表示驱动方向 | `N*m` | 不可用，需额外 CSV |
| 11 | `wheel_torque_fr` | 右前轮轮端驱动/制动力矩 | `N*m` | 不可用，需额外 CSV |
| 12 | `wheel_torque_rl` | 左后轮轮端驱动/制动力矩 | `N*m` | 不可用，需额外 CSV |
| 13 | `wheel_torque_rr` | 右后轮轮端驱动/制动力矩 | `N*m` | 不可用，需额外 CSV |
| 14 | `tire_fx_fl` | 左前轮胎纵向力 | `N` | 不可用，需额外 CSV |
| 15 | `tire_fx_fr` | 右前轮胎纵向力 | `N` | 不可用，需额外 CSV |
| 16 | `tire_fx_rl` | 左后轮胎纵向力 | `N` | 不可用，需额外 CSV |
| 17 | `tire_fx_rr` | 右后轮胎纵向力 | `N` | 不可用，需额外 CSV |
| 18 | `normal_load_fl` | 左前轮垂向载荷 `Fz` | `N` | 不可用，缺失时用静态载荷分配 |
| 19 | `normal_load_fr` | 右前轮垂向载荷 `Fz` | `N` | 不可用，缺失时用静态载荷分配 |
| 20 | `normal_load_rl` | 左后轮垂向载荷 `Fz` | `N` | 不可用，缺失时用静态载荷分配 |
| 21 | `normal_load_rr` | 右后轮垂向载荷 `Fz` | `N` | 不可用，缺失时用静态载荷分配 |
| 22 | `reverse_enable` | 倒挡/反向行驶标志，`1` 表示反向 | 二值 | 不可用，需额外 CSV |
| 23 | `rear_drive_enable` | 后驱工况标志，`1` 表示后驱逻辑启用 | 二值 | 不可用，需额外 CSV |
| 24 | `road_friction` | 轮胎-路面附着系数 `mu` | 无量纲 | 不可用，缺失时使用有界可学习参数 |

完整信号 CSV 的文件名为 `scene-XXXX.csv`，至少包含 `timestamp_us`，其他列使用上表字段名。Dataset 对每个时刻只查询“不晚于当前时刻的最近记录”，保证因果性；记录年龄超过 `physics_extra_max_age_sec` 后自动视为无效。CAN 消息同样受 `can_max_age_sec` 限制。

## 6. 动力学特征提取器输出接口

`CausalPhysicsVelocityEstimator` 返回三个端口：

```python
physics_velocity: Tensor    # [B,2]
physics_confidence: Tensor  # [B,2]
physics_features: Tensor    # [B,K,18]
```

### 6.1 速度与置信度

| 输出 | 分量 | 实际物理含义 | 单位 |
|---|---|---|---|
| `physics_velocity` | `[vx,vy]` | 当前窗口末端的车辆质心纵向、侧向速度估计 | `m/s` |
| `physics_confidence` | `[confidence_vx,confidence_vy]` | 纵向、侧向估计可靠程度，范围 `[0,1]` | 无量纲 |

`physics_confidence` 是根据测量有效性、轮速一致性、创新量和侧向激励构造的模型置信度，不是经过概率标定的统计概率。

### 6.2 18 维物理中间特征

| 索引 | 字段名 | 实际物理含义 | 单位 |
|---:|---|---|---|
| 0 | `vx_predict` | IMU 状态方程更新后的纵向先验速度 | `m/s` |
| 1 | `vx_wheel_observation` | 质心修正、打滑降权后的四轮速度观测 | `m/s` |
| 2 | `vx_estimate` | Kalman 更新后的纵向速度 | `m/s` |
| 3 | `vy_kinematic` | 运动学自行车模型得到的侧向速度 | `m/s` |
| 4 | `vy_dynamic` | 侧向动力学观测器积分状态 | `m/s` |
| 5 | `vy_estimate` | 运动学与动力学融合后的侧向速度 | `m/s` |
| 6 | `sideslip_angle` | 质心侧偏角 `atan2(vy,vx)` | `rad` |
| 7 | `yaw_rate` | 当前横摆角速度测量 | `rad/s` |
| 8 | `steering_angle` | 当前采用的道路轮等效转角 | `rad` |
| 9 | `ax` | 当前纵向加速度 | `m/s^2` |
| 10 | `ay` | 当前侧向加速度 | `m/s^2` |
| 11 | `wheel_speed_mean` | 当前有效车轮速度均值 | `m/s` |
| 12 | `wheel_speed_std` | 当前有效车轮速度标准差 | `m/s` |
| 13 | `slip_score` | 综合轮速差和轮加速度偏差的打滑评分 | `[0,1]`，无量纲 |
| 14 | `vx_innovation` | 轮速观测减去纵向预测，即 Kalman 创新 | `m/s` |
| 15 | `lateral_excitation` | 横摆、转角和侧向加速度构成的侧向激励程度 | `[0,1]`，无量纲 |
| 16 | `confidence_vx` | 纵向速度置信度 | `[0,1]`，无量纲 |
| 17 | `confidence_vy` | 侧向速度置信度 | `[0,1]`，无量纲 |

如果还需要神经网络动力学潜在特征，则把 `physics_features` 输入物理 GRU：

```text
physics_features [B,K,18]
  -> physics ChassisSequenceEncoder
  -> dynamics_feature [B,Dp]
```

混合主配置中默认 `Dp=64`，由 `model.branch_feature_dim` 控制。与运动学潜在特征一样，`dynamics_feature` 的每一维没有固定物理单位；可解释量应读取上面的 18 维物理中间特征，而不是解释 GRU 输出通道。

两个独立动力学配置含义不同：

```text
configs/velocity_xy_physics_only.yaml
  只训练受约束的因果物理状态估计器，作为纯机理基线。

configs/velocity_xy_physics_feature_only.yaml
  训练物理状态估计器 + 18维物理特征 GRU + 二维残差头，
  用于得到可迁移到混合模型的动力学特征提取器。
```

## 7. 监督输出与损失接口

两个分支共同使用同一监督端口：

```python
target_velocity = batch["velocity"]  # [B,2], m/s
```

标签分量为：

| 索引 | 字段 | 物理含义 | 单位 |
|---:|---|---|---|
| 0 | `target_vx` | 中心帧车体坐标系前向速度 | `m/s` |
| 1 | `target_vy` | 中心帧车体坐标系左向速度 | `m/s` |

运动学分支建议使用：

```text
L_kinematic = VelocitySmoothL1(pred_velocity, target_velocity)
```

动力学分支建议使用：

```text
L_dynamics = VelocitySmoothL1(physics_velocity, target_velocity)
           + 0.05 * SmoothL1(beta_physics, beta_target)
```

`sigma_vx=5.0`、`sigma_vy=0.5` 用于平衡纵向与侧向速度量级。训练/验证/测试必须按 scene 划分，不能把同一 scene 的相邻窗口随机分到训练集和验证集，否则会产生严重的时序泄漏。

## 8. 推荐的独立训练 Batch Contract

### 8.1 运动学分支

```python
kinematic_batch = {
    "chassis": FloatTensor[B, K, 16],
    "base_velocity": FloatTensor[B, 2],
    "velocity": FloatTensor[B, 2],
    "scene_name": list[str],
    "center_timestamp": LongTensor[B],
}
```

### 8.2 动力学分支

```python
dynamics_batch = {
    "physics_inputs": FloatTensor[B, K, 25],
    "physics_valid_mask": BoolTensor[B, K, 25],
    "physics_dt": FloatTensor[B, K],
    "chassis_current_index": LongTensor[B],
    "velocity": FloatTensor[B, 2],
    "scene_name": list[str],
    "center_timestamp": LongTensor[B],
}
```

## 9. 数据进入训练前的强制检查

1. `chassis`、`physics_inputs`、mask 和 `physics_dt` 的 `K` 必须一致。
2. `physics_dt` 必须有限且非负；`physics_dt[:,0]` 必须为 `0`，其余 20 Hz 规则采样间隔应接近 `0.05 s`。
3. `velocity` 必须是车体坐标系 `[vx,vy]`，不能混入全局坐标速度。
4. 边界帧没有前后 pose 时不能用零速度填充标签，应跳过样本。
5. `fair_chassis` 不得加入 pose 派生速度、加速度和旋转率。
6. 所有缺失动力学量必须由 `physics_valid_mask=False` 表示。
7. 启用动力学训练前必须确认轮速 `/1000`、转向 `/780`、反馈 `/7.7`、横摆率和加速度的单位及正负方向。
8. 单位审计完成前保持 `data.physics_units_audited: false`；物理训练入口会拒绝未审计配置。
9. 每个 scene 分别检查时间戳单调性、信号缺失率、极值和零值比例。
10. 单独报告低速、转弯、高侧向加速度、急加减速和轮速不一致工况的误差。
11. CAN 和完整物理 CSV 超过配置最大时延后必须失效，不能无限沿用旧测量。
