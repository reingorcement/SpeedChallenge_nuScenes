# 基于视觉-运动学-动力学融合的知识驱动纵侧向车速估计代码改造计划

## 0. 给新窗口 Cursor 的任务说明

请先阅读项目中的 `AI_CODE_CONTEXT.md` 和 `速度XY改造使用说明.md`，然后以实际代码为准执行本计划。当前项目不是旧版标量 `speed` 估计，而是 nuScenes ego/body frame 下的二维速度估计：

```text
target_velocity = [v_x, v_y]
base_velocity   = [base_vx, base_vy]
pred_velocity   = base_velocity + delta_velocity
```

本次改造目标是把现有 `FlexiNet_ChassisFusion` 从“视觉 + chassis 特征拼接融合”升级为：

```text
VisionBranch + KinematicBranch + DynamicsBranch + ConfidenceGatedFusion
```

研究题目建议表述为：

**基于视觉-运动学-动力学融合的知识驱动纵侧向车速估计方法**

不要推倒重写。优先在现有数据集、模型、训练和评估流程上做兼容式扩展。

## 2. 研究缺口与代码贡献

### Gap 1：现有融合没有区分视觉、运动学、动力学贡献

当前模型把 `images`、`chassis`、`flow`、`geometry` 编码后拼接进入 `FusionHead`。这能训练，但论文解释力不足：无法回答视觉何时有用、运动学何时失效、动力学先验如何约束估计。

代码贡献：

- 增加显式三分支。
- 增加门控融合权重。
- 保存或统计 gate 权重，用于解释不同场景下的模态依赖。

### Gap 2：EOVM-EKF 还只是 base velocity，没有进入知识分支

当前 `base_velocity_source: eovm_ekf` 可以把 EOVM 输出作为 `base_velocity`，但尚未成为一个可解释的动力学知识分支。

代码贡献：

- 把 `base_velocity` 和 chassis-derived proxies 组成 `dynamics` 特征。
- 用残差学习 `target_velocity - base_velocity`。
- 后续可加入 `prior_loss`，约束预测不要无理由偏离可靠物理先验。

### Gap 3：视觉有效性必须用消融和分场景证明

如果只汇报融合模型优于 baseline，不能证明“视觉适配纵侧向速度估计”。必须补齐：

- `vision_only`
- `kinematics_dynamics_only`
- `vision_kinematics`
- `vision_kinematics_dynamics`

并在转弯、高横向运动、轮速不一致等困难场景中单独比较。

## 3. 总体改造原则

1. **保持 batch contract 不变**`Dataset` 仍必须返回：

   ```python
   {
       "images": Tensor,
       "chassis": Tensor,
       "base_velocity": Tensor,
       "velocity": Tensor,
       "flow": Tensor,
       "geometry": Tensor,
       "base_speed": Tensor,
       "speed": Tensor,
       "scene_name": str,
       "center_token": str,
       "center_timestamp": Tensor,
   }
   ```
2. **保持默认旧配置可运行**旧的 `fusion_mode: residual` 不应被破坏。所有新增功能通过配置开启。
3. **新增损失默认权重为 0**先保证结构消融跑通，再逐步开启知识损失。
4. **`pose_assisted` 只作上限实验**不可作为可部署主结论，因为它可能与 ego pose 标签同源。
5. **先跑 smoke，再跑完整训练**
   每个阶段都先通过 `smoke_model.py`、`pytest`、`compileall`。

### 6.2 新增 `ProjectionBlock`

用于把不同分支投影到统一维度：

```python
class ProjectionBlock(nn.Module):
    def __init__(self, input_dim: int, output_dim: int, dropout: float = 0.1) -> None:
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(input_dim, output_dim),
            nn.ReLU(inplace=True),
            nn.Dropout(dropout),
        )

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        return self.net(x)
```

### 6.3 新增 `DynamicsProxyEncoder`

第一阶段输入来自 `base_velocity` 和 chassis proxy：

```text
base_vx
base_vy
yaw_rate
steering
steering_feedback
longitudinal_accel
transversal_accel
wheel_speed_std
```

建议实现：

```python
class DynamicsProxyEncoder(nn.Module):
    def __init__(self, input_dim: int = 8, hidden_dim: int = 64, output_dim: int = 64, dropout: float = 0.1) -> None:
        ...
```

### 6.4 新增 `ConfidenceGatedFusionHead`

输入三个同维度分支特征，输出 `delta_velocity` 和 gate：

```python
class ConfidenceGatedFusionHead(nn.Module):
    def __init__(self, feature_dim: int, hidden_dim: int, output_dim: int = 2, dropout: float = 0.3) -> None:
        ...

    def forward(self, branch_features: list[torch.Tensor]) -> tuple[torch.Tensor, torch.Tensor]:
        stacked = torch.stack(branch_features, dim=1)  # [B, M, D]
        gate_logits = self.gate_mlp(stacked.flatten(1))
        gate = torch.softmax(gate_logits, dim=1)       # [B, M]
        fused = (stacked * gate.unsqueeze(-1)).sum(dim=1)
        delta = self.pred_head(fused)
        return delta, gate
```

注意：

- 分支数量可变，`vision_only` 只有 1 个分支。
- 如果某分支关闭，不应传入全零特征参与 softmax；应直接从 branch list 中移除。

### 6.5 修改 `FlexiNetChassisFusion.__init__`

新增参数：

```python
use_vision_branch: bool = True
use_kinematic_branch: bool = True
use_dynamics_branch: bool = False
branch_feature_dim: int = 64
dynamics_feature_dim: int = 8
save_gate_weights: bool = False
```

初始化时：

- `use_vision_branch=True` 时创建视觉 projection。
- `use_kinematic_branch=True` 时创建 `ChassisSequenceEncoder`。
- `use_dynamics_branch=True` 时创建 `DynamicsProxyEncoder`。
- `fusion_mode == "residual_gated"` 时创建 `ConfidenceGatedFusionHead`。

### 6.6 修改 `forward`

建议 forward 保持签名：

```python
def forward(
    self,
    images: torch.Tensor,
    chassis_vec: torch.Tensor,
    base_speed: Optional[torch.Tensor] = None,
    base_velocity: Optional[torch.Tensor] = None,
    flow: Optional[torch.Tensor] = None,
    geometry: Optional[torch.Tensor] = None,
) -> torch.Tensor:
```

内部逻辑：

```text
if fusion_mode in {"residual", "direct"}:
    走旧逻辑

if fusion_mode == "residual_gated":
    branches = []
    if use_vision_branch:
        visual_feat = backbone + optional flow + optional geometry
        branches.append(projected_visual_feat)
    if use_kinematic_branch:
        kinematic_feat = ChassisSequenceEncoder(chassis)
        branches.append(projected_kinematic_feat)
    if use_dynamics_branch:
        dynamics_input = build_dynamics_proxy(chassis, base_velocity)
        dynamics_feat = DynamicsProxyEncoder(dynamics_input)
        branches.append(projected_dynamics_feat)
    delta, gate = gated_head(branches)
    pred = base_velocity + delta
```

如果 `fusion_mode == "direct"`，`vision_only` 可以直接输出 `pred_velocity`，不加 `base_velocity`。

### 6.7 gate 权重保存策略

第一阶段不强行修改所有评估 CSV。可以先在模型上保存：

```python
self.last_gate_weights = gate.detach()
self.last_gate_names = active_branch_names
```

后续评估阶段再把它写入 CSV。这样对训练侵入较小。

## 7. 训练与损失改造

目标文件：

```text
train.py
```

### 7.1 改造 criterion

现有：

```python
VelocitySmoothL1Loss(pred, target)
```

建议新增组合损失：

```python
class KnowledgeDrivenVelocityLoss(nn.Module):
    def __init__(
        self,
        sigma_vx: float,
        sigma_vy: float,
        speed_weight: float = 0.0,
        beta_weight: float = 0.0,
        prior_weight: float = 0.0,
        consistency_weight: float = 0.0,
        beta_vx_eps: float = 0.5,
    ) -> None:
        ...

    def forward(
        self,
        pred: torch.Tensor,
        target: torch.Tensor,
        base_velocity: torch.Tensor | None = None,
        chassis: torch.Tensor | None = None,
    ) -> torch.Tensor:
        ...
```

### 7.2 各损失定义

#### 主速度损失

```text
L_vel = SmoothL1(pred / sigma, target / sigma)
```

沿用现有 `sigma_vx=5.0`、`sigma_vy=0.5`。

#### 侧偏角损失

```text
beta_pred = atan2(pred_vy, clamp(abs(pred_vx), min=eps) * sign(pred_vx))
beta_gt   = atan2(gt_vy,   clamp(abs(gt_vx),   min=eps) * sign(gt_vx))
L_beta = SmoothL1(beta_pred, beta_gt)
```

低速时 `beta` 不稳定，可只在 `abs(target_vx) > beta_vx_eps` 的样本上计算。

#### 先验损失

```text
L_prior = SmoothL1(pred, base_velocity)
```

只在 `base_velocity` 可用时计算。第一阶段默认 `prior_loss_weight=0.0`，避免 EOVM 未审计时误导训练。

#### 一致性损失

弱约束即可，不要写强轮胎模型。可选：

```text
lateral_accel_proxy = target_vx * yaw_rate
```

但 nuScenes CAN 的单位和坐标需审计，第一阶段建议先不启用，即 `consistency_loss_weight=0.0`。

### 7.3 修改 `_model_forward_from_batch`

当前返回：

```python
return pred, velocity, base_velocity
```

可以保持不变。如果启用组合损失需要 `chassis`，则训练循环里直接从 batch 取。

训练循环中改为：

```python
if isinstance(criterion, KnowledgeDrivenVelocityLoss):
    loss = criterion(pred, velocity, base_velocity=base_velocity, chassis=batch["chassis"].to(device))
else:
    loss = criterion(pred, velocity)
```

更简单的方式：让 `KnowledgeDrivenVelocityLoss.forward` 的 `base_velocity`、`chassis` 都是可选参数；旧 loss 不动。

### 7.4 修改 `build_criterion`

支持：

```yaml
train:
  loss: knowledge_velocity
```

并读取：

```yaml
beta_loss_weight
prior_loss_weight
smoothness_loss_weight
consistency_loss_weight
beta_vx_eps
```

### 14.2 这些论文具体借用了哪些部分

这里的“借助文献”不是照搬某一篇论文的完整模型，而是把不同论文中已经成立的问题设定、传感器线索、物理先验和评估方式转成当前代码可实现的模块。

1. **二维速度与侧偏角定义**`A Camera-Based Methodology to Measure Longitudinal and Lateral Velocity of Vehicle Passenger Cars` 明确把纵向速度、横向速度和 sideslip angle 放在同一个测量问题中；`On the Vehicle Sideslip Angle Estimation` 综述说明侧偏角是车辆稳定性估计中的核心状态。因此当前代码不再只估计标量 speed，而是固定为 `target_velocity = [v_x, v_y]`，并把 `beta = atan2(v_y, v_x)` 作为辅助评价或辅助损失。
2. **视觉分支借用的是“相对运动线索”，不是具体相机安装方案**`AI-Based Vehicle State Estimation Using Multi-Sensor Perception and Real-World Data` 使用相机/激光雷达等感知数据，通过相对运动关系绕开轮胎模型依赖，特别强调低附着时轮速和转角可能不再可靠。`A Camera-Based Methodology...` 进一步说明相机可以直接服务于纵向、横向速度和侧偏角测量。当前项目没有照搬下视相机、激光雷达或 YOLO/Complex-YOLO 流程，而是把这些论文中的视觉运动线索落到已有输入 `images`、`flow`、`geometry` 上，形成 `VisionBranch(images, flow, geometry)`。
3. **运动学分支借用的是低成本车载信号组合**`Dynamic-Model-Free Vehicle Velocity Estimation Using Extended Kalman Filter with IMU, Steering Angle, and Wheel Speed Sensors` 和非线性观测器类论文都说明，IMU、转角、轮速、横摆率等底盘信号可以构成纵横向速度估计的传统基线。当前代码不在神经网络里重写完整 EKF/observer，而是把 `vehicle_speed`、`odom_speed`、`yaw_rate`、`steering`、`longitudinal_accel`、`transversal_accel`、四轮轮速和 `wheel_speed_std` 作为 `KinematicBranch(chassis)` 的输入来源。
4. **动力学分支借用的是“物理先验 + proxy 特征”思路**`Vehicle Velocity Estimation Using Nonlinear Observers`、`Nonlinear Observer for Longitudinal and Lateral Velocities...` 和 `Estimation of Lateral Velocity and Cornering Stiffness...` 都把轮胎力、侧偏、横摆、转角或 cornering stiffness 等动力学量作为不可直接测量状态的估计依据。当前第一阶段不强行建立完整轮胎模型，只把 `base_velocity`、`yaw_rate`、`steering`、`longitudinal_accel`、`transversal_accel`、`wheel_speed_std` 组织成 `DynamicsBranch(base_velocity, chassis_proxy)`。
5. **`base_velocity_source: eovm_ekf` 借用的是滤波器作为先验的角色**EKF、UKF、非线性观测器和 LSTM/adaptive Kalman filter 类论文的共同点是：物理或滤波框架给出稳定但可能有偏的状态估计，数据驱动模块再补偿复杂工况。当前代码因此采用 `pred = base_velocity + delta_velocity`，把 EOVM/EKF 输出作为 `base_velocity`，神经网络只学习残差 `delta_velocity`。这比直接让网络从零预测更容易解释，也方便和物理基线比较。
6. **门控融合借用的是“不同信息源可靠性随工况变化”**`Estimation of Lateral Velocity and Cornering Stiffness...` 先比较相机/车道线运动学估计和动力学估计，再用车辆动态特征计算融合分配系数；`AI-Based Vehicle State Estimation...` 则强调感知传感器可在低附着等传统车身信号失效场景补充信息。因此 `ConfidenceGatedFusion` 的目标不是单纯拼接特征，而是输出 `gate_vision`、`gate_kinematic`、`gate_dynamics`，用来解释不同场景下模型更依赖哪类信息。
7. **`beta_loss`、`prior_loss`、`consistency_loss` 是文献思想的轻量化版本**`beta_loss` 来自侧偏角估计文献对 `beta` 的核心关注；`prior_loss` 来自滤波器/物理先验论文中“不要无理由偏离物理估计”的思想；`consistency_loss` 来自运动学/动力学观测器中横摆率、横向速度和横向加速度之间的一致性关系。但由于 nuScenes CAN 信号单位、方向和 EOVM 可靠性还需要审计，这些损失第一阶段默认权重为 0，只作为可控开关保留。
8. **分场景评估借用的是文献中的工况意识**
   多数车辆状态估计论文不会只看全局平均误差，而会比较稳态、转弯、动态操纵、低附着、轮速/转角不可靠等场景。当前项目据此增加 `turning`、`high_lateral`、`wheel_inconsistent`、`hard_accel`、`high_lat_accel` 等分组指标，专门验证视觉分支是否在底盘信号不可靠或横向运动强的样本中带来收益。

### 14.3 最值得优先精读的三篇

1. `AI-Based Vehicle State Estimation Using Multi-Sensor Perception and Real-World Data`
2. `Estimation of Lateral Velocity and Cornering Stiffness in Vehicle Dynamics Based on Multi-Source Information Fusion`
